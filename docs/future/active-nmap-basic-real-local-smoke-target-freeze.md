# Active Nmap Basic Real Local Smoke Target Freeze

Decision:

```text
ACTIVE_NMAP_BASIC_17_REAL_LOCAL_SMOKE_TARGET_FREEZE_ACCEPTED
```

This is a docs-only readiness gate for a future real local authorized
`active_nmap_basic` smoke. It freezes the only allowed target, ports, command
shape, feature-flag handling, cleanup, rollback, evidence checklist, and no-go
criteria before any real execution can be considered.

This phase does not run Nmap, run Docker, execute probes, perform DNS checks,
make external HTTP requests, create migrations, create tags, create releases,
change backend/frontend/runner runtime, connect the backend to a real executor
by default, invoke a real subprocess, use a real external target, use a VPS,
use a domain, use a third party, add a runner HTTP endpoint, integrate
archive/run-all, or integrate Active into `tools/runner/main.py`.

## Objective

Freeze a narrow future smoke target so the next execution phase cannot drift
into arbitrary internet scanning, broad local network scanning, DNS expansion,
or ambiguous operator choices.

This document does not approve the future execution. It only defines the exact
target-control contract that a later execution phase must follow if real local
Nmap execution is separately approved.

## Current State

Accepted prerequisites:

- `ACTIVE_NMAP_BASIC_14_BACKEND_EXECUTOR_WIRING_MOCKED_NO_LIVE_ACCEPTED`
- `ACTIVE_NMAP_BASIC_15_LOCAL_SMOKE_PLAN_NO_UNAUTHORIZED_TRAFFIC_ACCEPTED`
- `ACTIVE_NMAP_BASIC_16_NO_LIVE_SMOKE_EXECUTION_PASSED`

The current backend still defaults to a no-live adapter. The first no-live
smoke passed with fake/mocked adapters only. Real Nmap execution, Docker/Nmap
packaging, backend default real-executor wiring, runner HTTP endpoints,
archive/run-all integration, `tools/runner/main.py` integration, VPS/domain
smoke, and public/third-party targets remain blocked.

## Frozen Target

Chosen target for the future real local smoke:

```text
127.0.0.1
```

Rationale:

- numeric loopback target;
- no DNS lookup required;
- no hostname resolution;
- no LAN, VPS, public internet, or third-party dependency;
- works without starting a separate service when paired with the frozen closed
  port below.

Explicitly not selected:

- `localhost`, because it can imply name resolution;
- `::1`, reserved only for a later IPv6-specific smoke if separately frozen;
- any hostname;
- any public domain;
- any VPS or owned domain;
- any private LAN address;
- any container address;
- any third-party target.

## Frozen Ports

Chosen port set for the future real local smoke:

```text
[65000]
```

Rationale:

- one exact TCP port;
- expected to be closed on a normal local workstation;
- no service startup required;
- no dependency on Docker or a local lab service;
- small enough to make evidence easy to reason about.

Explicitly not allowed:

- more than this one port for the first real local smoke;
- ranges;
- CIDR-derived port or target expansion;
- `-p-`;
- top ports;
- service discovery;
- any open-port validation that requires starting a local service.

If a future smoke wants to validate an open port, that must be a separate
target/service-freeze phase that names the exact local service, startup
command, shutdown command, port, logs, and cleanup. This document does not
approve that path.

## Frozen Profile And Command Shape

The future request must keep:

- `mode: live_nmap_basic`;
- `profile: tcp_connect_small`;
- `targets: ["127.0.0.1"]`;
- `ports: [65000]`;
- `authorization_confirmed: true`;
- `local_private_scope_confirmed: true`;
- `live_traffic_confirmed: true`.

The future runner argv, if a later execution phase explicitly approves real
local execution, must be generated by the allowlisted builder and match this
shape:

```text
["nmap", "-sT", "-Pn", "-n", "--max-retries", "1", "--host-timeout", "30s", "-oX", "-", "-p", "65000", "--", "127.0.0.1"]
```

No user-supplied raw command is approved. Operators must not type or pass raw
flags through the API. The backend/frontend request remains structured-only.

Still forbidden:

- raw flags;
- NSE;
- `--script`;
- UDP;
- SYN scan;
- OS detection;
- service/version detection;
- brute force;
- exploit scripts;
- credential validation;
- crawling;
- DNS expansion;
- target files;
- shell execution.

## Limits

Frozen limits for the future real local smoke:

- target count: exactly 1;
- target value: exactly `127.0.0.1`;
- port count: exactly 1;
- port value: exactly `65000`;
- profile: exactly `tcp_connect_small`;
- Nmap max retries: 1;
- Nmap host timeout: 30 seconds;
- process timeout: current bounded runner limit, expected 35 seconds;
- stdout XML cap: current bounded runner limit, expected 131072 bytes;
- stderr cap: current bounded runner limit, expected 16384 bytes;
- parse cap: current bounded runner limit, expected 131072 bytes;
- no concurrency expansion;
- no target expansion;
- no DNS expansion.

## Feature Flag

The future execution may set:

```text
INSPECTRA_ACTIVE_NMAP_BASIC_ENABLED=true
```

Only for the explicit smoke session.

The flag must be disabled immediately afterward. Prefer an inline environment
variable for the backend process used by the smoke so enablement disappears when
the process exits. Do not persist this value in shell profiles, service units,
checked-in docs as active configuration, or any `.env`, `.env.*`, or `.envrc`
file.

## Evidence Checklist For Future Execution

The future execution must verify:

- job audit type is `active_nmap_basic`;
- job is owner-scoped;
- `file_id: null`;
- target is exactly `127.0.0.1`;
- ports are exactly `[65000]`;
- request mode/profile are exactly `live_nmap_basic` and `tcp_connect_small`;
- `nmap_executed: true` appears only if the later phase explicitly approves
  real local Nmap execution;
- `subprocess_invoked: true` appears only if the later phase explicitly
  approves real local Nmap execution;
- `dns_queries_sent: 0`;
- no external HTTP traffic;
- API, reports, exports, frontend, and Raw JSON do not expose raw
  target/command/XML/stdout/stderr sensitive evidence;
- report wording stays observed exposure / review indicator / manual validation
  required;
- no confirmed vulnerability, exploitability, target-safety, full-scan, or
  all-ports-found claims.

`network_requests_sent` must be interpreted carefully. If the field remains a
logical metadata counter rather than a socket-level measurement, it must not be
used to claim that no local socket traffic occurred. The future execution
record should say exactly what the field measures at that time.

## Cleanup And Rollback

The future execution phase must:

- stop the backend process launched with `INSPECTRA_ACTIVE_NMAP_BASIC_ENABLED=true`;
- confirm no persistent feature-flag enablement remains;
- delete the smoke job if the phase records it as disposable;
- remove downloaded smoke exports if they are not intentionally retained as
  evidence;
- record that any OS-level local logs, shell history, browser cache, backups,
  and snapshots are outside Inspectra cleanup;
- leave real Nmap execution disabled again after the smoke.

If any no-go criterion occurs, stop the smoke, disable the feature flag, keep
real execution blocked, document the failure, and fix defects in separate
commits before trying again.

## No-Go Criteria

Abort the future smoke if any of the following occurs:

- any external DNS lookup;
- any target other than `127.0.0.1`;
- any external traffic not explicitly expected by the local backend/frontend
  development setup;
- any domain, VPS, third-party host, LAN target, container target, or hostname;
- any CIDR, range, wildcard, target file, pasted target list, or target
  expansion;
- any port other than `65000`;
- any raw flag;
- any NSE or `--script`;
- any UDP, SYN scan, OS detection, service/version detection, brute force,
  exploit script, credential validation, crawling, or DNS expansion behavior;
- any `shell=True`, `os.system`, `popen`, shell-string execution, or backend
  direct subprocess path;
- any archive/run-all trigger;
- any `tools/runner/main.py` integration;
- any raw target/command/XML/stdout/stderr sensitive leakage in API, exports,
  UI, or Raw JSON;
- any confirmed vulnerability, exploitability, target-safety, full-scan, scan
  the internet, or all-ports-found claim.
