Estado: **PR borrador con CI verde; no publicada, no estable y sin tag**.

La candidatura `0.3.0-beta.1` consolida el desarrollo posterior a la alpha
pasiva en `release-prep/inspectra-0.3-beta`, creada desde
`8e72f1e704f1fa05ff6cf72a70a697fda01b7d83`. La rama remota y el
[PR borrador #1](https://github.com/dreykdrk7/inspectra/pull/1) existen tras una
publicación autorizada y acotada; esto no constituye merge, tag ni release.

- Análisis pasivo, proyectos, inventario, hallazgos, comparación e informes.

  aceptación controlada descrita en `DEPLOYMENT_ACCEPTANCE.md`.

Consulte `CHANGELOG.md` y `docs/feature-matrix.md` para la lista funcional y el
estado exacto de cada proveedor/capacidad.

## Compatibilidad

- Python 3.12 para backend, herramientas y CLI.
- Node.js 22 para desarrollo/build del frontend.
- Docker Engine y Compose con soporte para `read_only`, `tmpfs`, límites de CPU,
  memoria/PID y reset de listas en overlays.
- Linux es la única plataforma de ejecución acreditada. macOS y Windows siguen
  bloqueados hasta disponer de evidencia real.
- El despliegue soportado continúa siendo single-host/single-worker.

La versión PEP 440 del wheel es `0.3.0b1`; la versión de producto/API/frontend
permanece `0.3.0-beta.1`. `make check-release` verifica esta sincronización.
La cadena de pruebas usa Vitest 4.1.11: es la primera versión estable corregida
para `CVE-2026-84373 / GHSA-82fw-gwwq-j7x9`; no se admite reconstruir esta
candidatura con el lock anterior de Vitest 3.x.

## Migración

No existe una migración manual general de datos para este corte. Antes de
probarlo sobre datos existentes:

1. detenga admisiones y espere/cancele ejecuciones;
2. cree y verifique un backup offline en almacenamiento cifrado;
3. restaure el backup a un directorio nuevo y valide readiness/login/listados;
4. conserve imágenes y configuración de la revisión anterior por digest;
5. no mezcle árboles parciales ni restaure encima del directorio activo.

El restore admite auth schema 1/2, migra 1→2, acepta team identity schema 1 y
rechaza versiones futuras. Proyectos/jobs/snapshots JSON se validan sin una
transformación masiva. Los índices derivados pueden reconstruirse; una
corrupción autoritativa es `NO-GO`. Detalles y reversión:
`docs/backup-restore.md` y `DEPLOYMENT_ACCEPTANCE.md`.

## Instalación de evaluación

El modo local confiable se inicia con:

```bash
docker compose config --quiet
docker compose up --build
```

No habilite egress ni Active para el primer smoke. Para un entorno privado use
el overlay documentado, un archivo de entorno `0600` fuera del repositorio,
almacenamiento cifrado y un host TLS real. Nunca reutilice credenciales de
aceptación.

## Puertas de la candidatura

Antes de considerar el tip candidato como reconstruible deben pasar:

- suites backend, contratos, herramientas, CLI y frontend sin omisiones;
- TypeScript, build y presupuesto de bundle;
- `pip check`, auditorías de cinco locks Python y auditoría npm;
- `compileall` y todos los perfiles Compose documentados;
- Gitleaks en historial, rama, staging/árbol y canario;
- sincronización de versiones/backlogs y `git diff --check`;
- wheel, sdist y SBOM reproducibles por digest;
- smoke sintético offline, sin proyecto u objetivo externo.

La evidencia local se incorpora a `PROD-129`; la puerta remota corresponde a
`SEC-012` y `PROD-130`. La ejecución
[34520803043](https://github.com/dreykdrk7/inspectra/actions/runs/34520803043)
terminó verde sobre `ef046a1fe2d8468aed6bfa83315ab7ae687bf922`: 2.094 pruebas
Python de backend/herramientas, 65 de CLI y 420 de frontend; build y presupuesto
de bundle; cinco auditorías Python y npm sin vulnerabilidades conocidas; dos
perfiles Compose; historial Gitleaks de 363 commits y canario. Todos los pasos
terminaron y CI publicó cero artefactos. Las acciones externas se ejecutaron por
SHA completo con permisos globales `contents: read`.

GitHub mostró una advertencia no bloqueante porque las revisiones fijadas de
checkout/setup todavía declaran Node 20 y el runner las fuerza a Node 24. La
migración a revisiones oficiales con runtime Node 24 nativo queda registrada en
`SEC-021`; no se actualiza de forma oportunista durante este corte.
