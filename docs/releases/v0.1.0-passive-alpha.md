# Inspectra Passive Technical Alpha v0.1.0

Tag: `v0.1.0-passive-alpha`

Status: trusted local technical alpha.

Decision: `READY_TO_TAG_PASSIVE_ALPHA` at pre-tag smoke.

## A. Summary

Inspectra Passive Technical Alpha is a trusted local technical alpha for passive review of uploaded files and archives. It is intended for local defensive and educational use with known, authorized inputs.

Findings are heuristic review indicators, not confirmed vulnerabilities, exploitability claims, breach claims, live reachability proof, or credential-validity proof. Results, exports, and Raw JSON use best-effort `[REDACTED]` redaction for sensitive-looking values, but uploaded originals are not sanitized and remain local files until removed.

This alpha is not production-ready and is not intended for external users, multi-user SaaS use, unattended handling of real sensitive archives, or public deployment.

## B. Included Scope

- Local upload workflow for files and archives.
- File/archive registration and local result storage.

## F. Security And Non-Scope

This release does not include:

- Exploitation.
- Active scanning.
- Nmap, port scanning, or network scanning.
- Credential validation.
- Live reachability claims.
- CVE/advisory lookup for passive config modules.
- Execution of uploaded projects, package managers, workflows, Docker, Compose, Terraform/OpenTofu/Terragrunt, Nginx, Kubernetes, Redis/Sentinel, SQL clients, or database servers for passive config modules.
- Provider, registry, reputation, or cloud API validation for passive config modules.
- Production, public, external-user, or multi-user readiness.

The authorized web, domain, and subdomain flows remain separate bounded baseline audit families with explicit authorization confirmation.

## G. Known Limitations

- Trusted local demo only.
- No authentication or deployment hardening.
- Local storage retains uploaded originals and job results until removed.
- Uploaded originals are not sanitized by redaction.
- `PassiveReportShell` is not applied to every report yet.
- Export presentation polish remains backlog.
- Synthetic fixtures demonstrate product behavior, not real-world completeness.
- Heuristic analyzers can produce false positives and false negatives.
- Archive-based config analyzers do not prove live exposure, exploitability, compromise, or credential validity.
