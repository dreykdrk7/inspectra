# Inspectra 0.3.0-beta.1

> **Prerelease beta:** no es una versión estable ni un despliegue de producción.

Commit publicado: `{{RELEASE_COMMIT}}`

Inspectra es una plataforma local-first y self-hosted para analizar proyectos
propios o expresamente autorizados. Esta prerelease reúne proyectos y ejecuciones
reproducibles, análisis pasivo, inventario, hallazgos priorizados, triage,
comparación, informes, CLI/CI e importación SBOM.

## Inteligencia y seguridad

- OSV para identidades npm públicas exactas tiene aceptación real acotada.
- CISA KEV enriquece únicamente CVE ya correlacionados; no determina por sí
  solo que una versión sea vulnerable.
- GHSA, NVD, OSV PyPI y otros ecosistemas continúan validados solo mediante
  fixtures o requieren una aceptación separada.
- El egress y todas las capacidades Active están deshabilitados por defecto.
- Active es experimental y solo puede utilizarse sobre activos propios o con
  autorización verificable.
- «Sin hallazgos conocidos» no equivale a «seguro».

## Compatibilidad y límites

- Linux es la única plataforma acreditada.
- Python 3.12 y Node.js 22 son los runtimes de desarrollo/build.
- La arquitectura soportada es single-host y single-worker, sin promesa de alta
  disponibilidad.
- Los assets wheel y sdist distribuyen la CLI; backend y frontend se ejecutan
  desde el código etiquetado mediante los perfiles Compose documentados.
- `PROD-256`: los webhooks opt-in conservan un riesgo residual de segunda
  resolución DNS y deben permanecer apagados salvo entorno controlado.
- `PROD-257`: algunos controles todavía ofrecen objetivos táctiles inferiores
  a 44 px.

## Instalación y verificación de la CLI

Descargue los cuatro assets en un directorio vacío y verifique primero:

```bash
sha256sum -c SHA256SUMS
python3.12 -m venv .venv
.venv/bin/python -m pip install --no-deps ./inspectra_cli-0.3.0b1-py3-none-any.whl
.venv/bin/inspectra --version
.venv/bin/inspectra doctor
```

`doctor` requiere Git y Gitleaks 8.x para declarar el entorno listo; un estado
`not_ready` con una dependencia externa ausente es una degradación explícita, no
una instalación exitosa falsamente presentada como operativa.

Para evaluar la aplicación completa, siga el
[README](https://github.com/dreykdrk7/inspectra/blob/v0.3.0-beta.1/README.md), la
[aceptación de despliegue](https://github.com/dreykdrk7/inspectra/blob/v0.3.0-beta.1/DEPLOYMENT_ACCEPTANCE.md)
y las instrucciones de
[backup y reversión](https://github.com/dreykdrk7/inspectra/blob/v0.3.0-beta.1/docs/backup-restore.md).
No habilite egress ni Active durante el primer smoke local.

## Integridad y procedencia

`SHA256SUMS` cubre wheel, sdist y SBOM CycloneDX 1.6. Los artefactos se
construyen dos veces y se comparan byte a byte con `SOURCE_DATE_EPOCH` fijo. El
workflow temporal de GitHub está ligado al SHA exacto de `main`, usa permisos de
solo lectura y no publica en registros externos. Esta prerelease no incluye una
firma ni una attestation criptográfica; la procedencia verificable es el run de
GitHub Actions enlazado desde la publicación.
